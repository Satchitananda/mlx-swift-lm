# Native EmbeddingGemma 2

`MLXVLM.EmbeddingGemma2Container` is a dedicated bidirectional encoder. It has
no chat template, generation loop, or autoregressive KV cache. Pass a local
checkpoint and your application's `TokenizerLoader` to `load(directory:tokenizerLoader:towers:)`.
The default tower set includes vision and audio; `[]` loads text only.

`embed(_:)` accepts ordered `EmbeddingGemma2Part` values: text, upright sRGB
images, timestamped video frames, and mono 16 kHz floating-point audio. A video
part contains visual input; supply its soundtrack as a separate audio part.
The caller owns file decoding, chunk selection, query/document task prefixes,
and the durable vector-space signature. Output contains an evaluated normalized
FP32 vector and the fully expanded token count. Arrays/modules stay inside one
exclusive `SerialAccessContainer`.

`embedBatch(_:)` accepts 1...4 independent ordered parts arrays and returns one
output per input. Preprocessed media is retained only for the current bounded
chunk; caller-owned primitive inputs remain the caller’s memory responsibility.
Expanded-token and batch-token limits split inference without
truncating requests; different token lengths use separate batches to preserve
individual attention shapes. Padded collation excludes padding from attention
keys and pooling and keeps padding queries finite beyond the sliding window.
Equal-shaped vision inputs can share batches of 1...8 frames (default 2 for
the batch API); the audio tower still encodes individual inputs. `embed(_:)`
retains its single-frame vision schedule. This API does not merge videos into
one joint vector or expose MLX tensors across the container boundary.

Loading verifies every required tensor and tokenizer special token. BF16 and
FP32 are supported; affine quantization and FP16 are rejected. Requests are
bounded to 8192 expanded tokens, 32 frames per video part, 30 seconds per audio
part, and 32 megapixels per image. Aggregate media budgets are checked while
preparing input, before allocating every requested media tensor.

Reference pins:

- `google/embeddinggemma-2`, source `914f7f89142e33e77833254d9c9b90c3cef7303b`
- `mlx-community/embeddinggemma-2-bf16`, conversion `1a4ffddb7905d3f63486748deabe091a01fb6201`
- Python mlx-vlm `fec3f50379bb2cb0760ef3c8a68ebce9585e4d97`

The synthetic fixtures in `Tests/MLXLMTests/Resources/EmbeddingGemma2` contain
deterministic tiny weights, expected encoder outputs, PIL RGB resize results,
and log-mel features. Regenerate with `generate_fixture.py` in the pinned Python
environment. They contain no pretrained weights or user media.

Run `swift test --filter EmbeddingGemma2Tests` with the platform's MLX Metal
library available. The optional full-checkpoint test additionally reads
`EMBEDDINGGEMMA2_CHECKPOINT` and `EMBEDDINGGEMMA2_PARITY`; the latter directory
is generated by CatalogKit's `Scripts/EmbeddingGemma2/native_reference.py`.
It checks 12 ordered text/image/video/audio/batched combinations and text-only
tower loading against the pinned reference at cosine > 0.9995.

Text rejects all tokenizer-registered BOS/EOS/media control strings, including
controls split across adjacent text parts. Vocabulary bounds and sub-frame
audio fail closed before unsafe gathers. Audio context-left 0/1 retains the
current frame. CatalogKit adds a separate raw URL/text proof with explicitly
tagged sRGB synthetic video; decoder color conventions are part of its native
recipe rather than the model vector-space identifier.
